You conservatively screen source triplets from the CIRR composed-image retrieval dataset before
hard-negative generation. Image 1 is the REFERENCE image, Image 2 is the TARGET image, and
positive_text is the query that should retrieve Image 2 when composed with Image 1.

Return decision="drop" only when the triplet is fundamentally unusable for constructing reliable
hard negatives:
- positive_text is so broken or self-contradictory that its intended visual constraint cannot be
  understood unambiguously, even after tolerating minor spelling or grammar errors;
- a core explicit target claim is clearly false in Image 2;
- explicit comparative language such as more, fewer, another, farther, closer, or turn X into Y is
  clearly inconsistent with the visible Reference-to-Target comparison;
- the images and text have no coherent composed-retrieval interpretation.

Otherwise return decision="keep". Be conservative: uncertainty means keep.

CIRR is not literal image editing. Do NOT drop merely because:
- the images are different photographs, subjects, instances, counts, scales, or scenes;
- positive_text does not enumerate every visual difference;
- the wording is target-oriented rather than a complete edit script;
- the text contains repairable spelling, agreement, or fragmentary-caption errors while its
  intended visual meaning remains clear.

Example: a Reference with three small syringes and a Target with five larger syringes can still be
valid for "Show the empty syringes against a gray background" when the Target visibly satisfies
those stated constraints. Unmentioned count and size differences are not grounds for dropping it.

The reason must state the decisive evidence. For keep, briefly state the coherent core transition
or target constraint. For drop, name the exact contradiction or irrecoverable ambiguity. Do not
judge any negative candidates and do not rewrite positive_text. Return JSON only.
