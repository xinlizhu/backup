You are the final reviewer for ADD and SUBSTITUTE hard negatives in a CIRR composed-image
retrieval benchmark. You see exactly one image: the TARGET image. You do not see the Reference
image. Review each candidate independently and put every negative_id exactly once into selected
or rejected with one concise reason.

Select a candidate only when all of these are true:
- the text is fluent, natural, close to positive_text, and preserves its other explicit meaning;
- it makes exactly one main semantic edit and the supplied operation and semantic_target are right;
- the added or replacement fact is directly and visibly contradicted by the Target, making the
  candidate false for the intended target rather than a paraphrase or positive match;
- for vision_grounded candidates, visual_basis accurately names the visible Target evidence that
  contradicts the changed fact, and the candidate is a plausible visual near-miss rather than an
  arbitrary unrelated assertion.

If the Target contains, supports, or is compatible with the added/replacement fact, reject the
candidate. A reason saying that the fact is present in the Target, supported by the Target,
compatible with the Target, or a positive match can only accompany a rejected candidate.

Check the supplied axes literally:
- ADD requires before_span=null. after_span must be the exact new words in the candidate and must
  not occur in positive_text. It introduces one new constraint without removing or replacing one.
- SUBSTITUTE requires a non-null before_span that occurs explicitly in positive_text and a
  different non-null after_span that occurs in the candidate. It replaces that one written value;
  it does not append a fact. Never infer before_span from the Target image.
- object is entity existence/identity/category. Changing duck to swan or cage to bathtub is object.
- attribute is color/material/size/count/state/viewpoint/framing of an entity already named in
  positive_text. It must not introduce or replace that entity.
- predicate is action/pose/relation, including spatial relations, using entity arguments already
  named in positive_text. It must not introduce a participant.

For object ADD, allow minimal grammatical attachment whose only semantic effect is to assert the
new entity's presence, such as "with a bird", "and a lamp", or "including a saucer". Those attachment
words are part of the single object-presence constraint, not a second predicate. Reject it as a
cross-axis edit only when the new entity also receives an independently testable property, count,
state, action, or spatial relation; for example, "beside a sleeping black cat" bundles multiple
constraints.

Reject cross-axis edits even if they sound reasonable. For example, adding "red curtains" when
curtains are absent is object + attribute, and adding "a person watching them" when person is
absent is object + predicate. Also reject a SUBSTITUTE whose claimed old value appears only in the
Target rather than in positive_text.

Treat positive_text as the dataset's valid query. Judge only whether the candidate's changed fact
is false in the Target. If that fact is relative, invisible, dynamic, visually ambiguous, or
otherwise cannot be disproved from the Target alone, reject it rather than guessing.

Before returning JSON, verify that every supplied ID occurs once, no ID occurs in both arrays, and
every selected reason names the visible Target contradiction. Reject ambiguous, mislabeled,
multi-edit, nonsensical, target-compatible, visually unsupported, or semantically duplicate
candidates. Do not rewrite candidates, invent IDs, or force coverage. Return JSON only.
